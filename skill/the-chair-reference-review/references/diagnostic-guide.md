# 推荐信诊断细则

默认输出只呈现核心判断。Full Audit 才展开全部检查项。

## 1. 推荐资格与观察基础

把两个问题分开：

### 正式资格与独立性

检查：

- 官方是否要求 academic / professional referee、职位、任职机构或官方邮箱；
- 推荐人是否存在亲属、同辈、下属、付费顾问、商业伙伴或其他利益冲突；
- 推荐人是否符合独立性和提交身份要求；
- 推荐人职位是否被错误地当作正式资格或内容质量的替代品。

官方规则缺失时，将正式资格标记 `not assessable`，不要推断合格或不合格。

### 观察基础

检查：

- 双方关系、相识时间、场景与接触强度；
- 推荐人实际观察或正式接触过的工作；
- 评价是否超出关系允许的范围；
- 比较群体是否真实、口径明确并属于推荐人的观察范围；
- 关系深度是否足以支撑推荐强度。

名气很大但接触很浅的推荐人，未必比持续指导申请者的老师或主管更有说服力。

## 2. 证据可信度与辨识度

### 形容词删除测试

删除 `excellent`, `outstanding`, `diligent`, `talented`, `responsible` 等评价词后，检查是否仍能看出：

- 申请者做过什么；
- 如何行动、判断或回应反馈；
- 与他人或常规做法有什么差异；
- 产生了什么结果、变化、产出或持续表现；
- 推荐人据此形成了什么判断。

### 接受多种证据形式

不要强迫所有推荐信讲一个完整故事。以下都可以成为有效证据：

1. **具体场景**：一个项目、问题或互动；
2. **长期模式**：多次作业、持续研究或稳定行为；
3. **正式记录**：评分、考核、项目日志或工作成果；
4. **比较判断**：有明确范围和观察基础的相对表现；
5. **重复互动**：多次反馈、修订、协作或独立推进；
6. **观察性综合评价**：由多项已说明的观察共同支持的判断。

不是每项证据都需要数字或戏剧性结果。关键是推荐人能否合理接触、记忆并认可。

### 推荐人视角与所有权

分别核查：

- **事实准确**：申请者是否可以确认事情发生过；
- **观察权限**：推荐人是否在场、指导、评分或接触正式记录；
- **解释所有权**：推荐人是否认可该事实所支持的能力判断；
- **推荐所有权**：比较、预测和推荐强度是否确为推荐人的判断。

申请者确认事实，不足以把它写成推荐人的第一手观察。正式记录可以支持精确数字，但应说明推荐人为何能接触该记录。

## 3. 项目相关性与材料组合

### 项目或领域相关性

建立：

> 项目或领域需求 -> 推荐人观察到的证据 -> 可信的学习或研究准备

官方题目优先。对于可重复投递的通用推荐信，判断它是否支持目标领域或项目类型，不要求逐校列课程。

以下通常不足：

- 只替换学校和项目名称；
- 重复官网口号；
- 罗列推荐人没有合理依据讨论的课程兴趣；
- 从普通参与直接跳到确定性的卓越预测。

### 材料组合功能

判断推荐信是否提供：

- 第三方观察；
- 申请者无法自行证明的比较或反馈；
- 对 CV 经历的独立验证；
- 对 PS 能力主张的外部支撑；
- 与其他推荐信不同的观察场景或能力维度。

CV、PS 或其他推荐信缺失时，只把材料组合功能标记 `not assessable`；仍然判断项目或领域相关性。

对多封信建立：

| 推荐人 | 正式身份 | 观察场景 | 最强可验证能力 | 项目/领域关系 | 与其他信重叠 |
|---|---|---|---|---|---|

## 4. 官方题目、文体与语气

官方 prompt、结构化问卷和提交规则覆盖默认四段结构。常见四个证据功能仍可用于自由文本：

1. 关系、资格与总体判断；
2. 核心证据；
3. 第二能力或长期模式；
4. 适配结论与推荐强度。

不同体系对克制、热情、排名和保留意见的表达习惯可能不同。只有在掌握可靠语境时，才把 hedging、含蓄表达或缺少最高级判断为 faint praise。

同时检查：

- 是否存在未解释的保留意见或关键能力沉默；
- 推荐强度是否与关系、证据和比较基础相称；
- 是否出现突然增加、前文未支持的能力；
- 是否像申请者 PS 的自我反思或项目官网摘要。

## 5. 正式提交与一致性

检查：

- 姓名、代词、日期、职位、机构、学校与项目；
- 占位符、复制残留和多校信息；
- 推荐人邮箱、签名、抬头和官方提交方式；
- 事实与 CV、PS、其他推荐信是否冲突；
- 推荐人身份是否满足系统要求。

未上传证明本身不是不可信。只有内部矛盾、明显越权、虚假精确、无依据比较或材料冲突才构成 `credibility risk`。

## 6. 规范化问题类型

只使用以下一级标签：

- `basis gap`：正式资格、独立性、关系或观察基础不足；
- `evidence gap`：评价缺少可观察或可核验的支持；
- `wording gap`：证据存在，但表达含混、冗长或套话化；
- `vantage-point gap`：信息超出推荐人可合理知道的范围；
- `comparison gap`：比较范围、口径或观察基础不清；
- `fit gap`：证据没有连接到项目或领域的真实需求；
- `portfolio gap`：与其他材料重复，却没有新增外部视角；
- `credibility risk`：矛盾、误导归属、冒充观察或其他实质可信度风险；
- `submission risk`：身份、占位符、格式或官方提交要求存在问题。

可在 `basis gap` 下说明 formal eligibility、conflict、relationship 或 observation 子类型，但不要创造新的一级标签。

## 7. 严重度与归因

- **局部**：只影响一个句子或次要评价，不改变整体理解；
- **反复出现**：多个重要评价存在同类缺口，实质削弱一个维度；
- **结构性**：正式身份不合规、缺乏可信观察基础、主体没有可辨识证据、明显冒充推荐人视角、重大事实冲突或无法提交。

给每个问题指定一个主要归属维度。只有产生不同读者后果时，才在其他维度再次影响分类。
