# 推荐信定性诊断输出结构

使用用户的语言，不给默认总分。分类只使用：

`convincing / convincing with local gaps / developing / structural risk / not assessable`

## A. Focused Stage 1：先判断

只输出诊断，不输出修改动作或示范文本。

### 1. 诊断依据与边界

简要列出申请类别、项目或领域、官方要求、推荐人身份与关系、观察场景、本信预期承担的能力侧面、材料组合信息，以及缺失内容影响哪些判断。说明本信功能是使用者指定、官方要求，还是根据证据暂定推断。

### 2. 一句话总判断

围绕本信的预期功能，说明已经成立的部分和最高影响的限制点，不给数字总分。不得因为本信未覆盖其他推荐人可以承担的能力而降低总判断。

### 3. 招生官最可能记住什么

用一至两句话写出申请者形象，并说明它来自具体证据还是作者宣称。

### 4. 三个核心判断

#### 4.1 推荐资格与观察基础

分别报告：

- 正式资格与独立性：`classification`
- 观察基础：`classification`
- 综合判断与招生官后果

#### 4.2 证据可信度与申请者辨识度

报告一个 `classification`。

#### 4.3 项目契合、单封信功能与组合覆盖

分别报告：

- 项目或领域相关性：`classification`
- 单封信功能：`classification`
- 整套组合覆盖：`classification`
- 综合判断与招生官后果

项目相关性只问本信有证据的能力侧面是否对目标项目具有实质意义，不要求一封信证明全部项目能力。缺少 CV、PS 或其他推荐信时，只把整套组合覆盖标记 `not assessable`；不得牵连单封信功能、项目相关性或总体分类。对本信预期功能之外、且官方未要求的能力沉默保持中性。

每个可判断项目依次说明：

- **已成立的证据**；
- **限制点与严重度**；
- **综合判断**；
- **招生官后果**；
- **判断边界**：只写会改变判断的事实条件，不使用“补充、删除、改写、加入”等修改动词。

某个子项缺少信息时，只将该子项标记 `not assessable`，不得牵连其他子项。如果本信功能只能根据现有证据推断，仍可暂定分类，但必须显式标注“待使用者确认的功能解释”。

如果某项没有成立证据，明确写“现有材料未建立该功能”，不要虚构正面内容。

### 5. 与用户校准

询问：

1. 哪些关系、观察或项目假设与事实不符；
2. 哪些事实仅由申请者确认，哪些推荐人确实观察并认可；
3. 本信预期承担什么能力侧面、其他推荐信分别承担什么，以及哪些官方要求或材料分工仍未提供。

不要把用户“认可判断”当作证据。

## B. Focused Stage 2：校准后建议

### 1. 校准后的结论

说明哪些判断维持、修改或撤回，以及新增事实。

### 2. 最多三个修改优先级

按依赖顺序：

1. **Structural**：正式资格、推荐人选择、观察基础、信件功能或证据架构；
2. **Major**：重构关键证据、项目相关性或材料分工；
3. **Local**：压缩套话、校准细节和强度、统一语言或格式。

每项包括：对应判断、短证据、修改目标、具体动作、事实确认责任。

事实确认责任固定标记为：

- `Applicant fact check`
- `Recommender access check`
- `Recommender assent required`
- `Official source check`

### 3. 最多五处高价值标注

```text
原句：<短引文>
问题类型：<规范化一级标签>
为什么影响判断：<招生官视角>
确认责任：<四类之一>
修改方向：<结构与信息要求>
```

事实已经确认且用户明确要求时，可对最多三处给出局部示范。不得生成整封替代信，不得把申请者确认的事实直接写成推荐人的观察或判断。

### 4. 四个证据功能的处理决定

| 功能 | 当前作用 | 核心证据 | 决定 |
|---|---|---|---|
| 关系、资格与总体判断 |  |  | 保留 / 压缩 / 补证 / 重建 |
| 核心证据 |  |  | 保留 / 深挖 / 合并 / 删除 / 重建 |
| 第二能力或长期模式（仅当本信承担） |  |  | 保留 / 深挖 / 合并 / 删除 / 重建 |
| 适配与推荐强度 |  |  | 保留 / 校准 / 补证 / 重建 |

## C. Combined response

仅在用户明确要求“判断和建议一起给”时使用。完整输出 A，再单独输出 B；缺失信息仍保持 `not assessable`，不能由建议代填。

## D. Full Audit

先输出 A，再增加：

- 每个段落或结构化回答字段的功能地图；
- 所有主要评价的证据形式与所有权检查；
- 推荐资格、利益冲突和观察范围；
- 形容词删除与申请者辨识度；
- 本信预期功能、项目/领域相关性、单封信贡献与整套材料分工；
- 推荐强度、保留意见和文体语境；
- 姓名、代词、项目、占位符、签名、抬头与提交要求；
- 最多八处代表性高价值标注。

必须覆盖全部段落或字段；重复问题可以合并，不必逐句重复。Full Audit 默认在诊断后暂停，不提供示范改写。只有用户同时明确要求 repair plan 时，才在其后增加 B。
