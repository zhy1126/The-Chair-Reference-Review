# 推荐信定性诊断输出结构

默认使用“先判断、后建议”的 Focused Review。使用用户的语言输出，不给默认总分。

## A. Focused Review 第一阶段：判断

第一阶段只输出诊断，不输出详细改写方案。

### 1. 诊断依据与边界

简要列出：

- 申请类别、学校与项目；
- 推荐人身份、关系、观察时间与场景；
- 官方要求与篇幅限制；
- 已提供的 CV、PS 或其他推荐信信息；
- 缺失材料以及哪些判断因此受限。

### 2. 一句话总判断

用一句话同时说明已经成立的部分和真正限制推荐信说服力的部分。例如：

> 这封信已经建立了可信的师生关系和一段可辨识的研究观察，但第二主体段仍主要依赖品质形容词，尚未把推荐人的独立证言收束为对目标项目准备度的明确判断。

不要给数字总分。

### 3. 招生官读完最可能记住什么

用一至两句话写出当前信件留下的申请者形象，并指出这一形象是由具体证据形成，还是主要由作者宣称形成。

### 4. 三个核心判断

固定使用：

1. 推荐资格与观察基础
2. 证据可信度与申请者辨识度
3. 项目契合与材料组合功能

每项使用 `convincing / convincing with local gaps / developing / structural risk / not assessable`，并依次写：

- **已成立的证据**：先说明该维度已经完成了什么；
- **限制点**：说明问题是局部、反复出现还是结构性的；
- **综合判断**：用一句话作出定性结论；
- **招生官后果**：说明读者为何会相信、犹豫或忽略；
- **判断边界**：说明缺少什么信息，或什么事实会改变判断。

项目或材料组合信息缺失时，必须标记 `not assessable`，不能因此下调其他两项。

### 5. 需要用户校准

固定以可回应的方式结束：

> 以上是第一轮判断，还不是修改方案。请告诉我：①哪些判断你认可；②哪些不认可；③推荐人实际还观察过哪些可补充的场景，或这封信在整套材料中必须承担什么功能。你确认后，我再给出最多三个修改优先级。

## B. Focused Review 第二阶段：建议

用户确认、纠正或补充判断后再输出。

### 1. 校准后的结论

简要说明哪些判断维持、修改或撤回，以及依据。

### 2. 三个修改优先级

最多三项，按依赖顺序排列：

1. **Structural**：推荐人选择、观察基础、信件功能或证据架构；
2. **Major**：重构一段关键证据故事或项目契合链；
3. **Local**：压缩套话、校准细节、调整推荐强度、统一格式或事实。

每项包括：对应判断、短证据、修改目标、具体动作、仍需确认的事实。

### 3. 高价值段落标注

最多标注五处：

```text
原句：<短引文>
问题类型：<wording gap / evidence gap / vantage-point gap / fit gap / portfolio gap / credibility risk / submission risk>
为什么影响可信度：<招生官视角>
需要补充或确认：<只有推荐人或申请者能确认的事实>
修改方向：<结构与信息要求，不虚构成稿>
```

若事实已经确认且用户明确要求，可以对最多三处给出示范性局部改写。不得擅自生成整封替代信，也不得把未确认内容写成推荐人的第一手观察。

### 4. 四个功能的处理决定

| 功能 | 当前作用 | 核心证据 | 决定 |
|---|---|---|---|
| 关系与资格 |  |  | 保留 / 压缩 / 补证 / 重建 |
| 核心故事 |  |  | 保留 / 深挖 / 合并 / 删除 / 重建 |
| 品质与第二维度 |  |  | 保留 / 深挖 / 合并 / 删除 / 重建 |
| 契合与推荐强度 |  |  | 保留 / 校准 / 补证 / 重建 |

### 5. 必要事实问题

只询问会直接影响上述修改动作的关系、场景、行动、结果、比较口径或官方要求。不要询问已知信息。

## C. Full Audit

只有用户明确要求全面审核、逐段检查、逐句标注或多封信组合审计时使用。在三项核心判断之后增加：

- 全段功能地图；
- 所有主要评价的“评价—场景—行动—结果”证据表；
- 形容词删除测试结果；
- 推荐人视角真实性检查；
- CV、PS 与多封推荐信的分工表；
- 推荐强度校准；
- 姓名、代词、项目、占位符、签名、抬头与提交要求核查；
- 最多八处高价值标注。

无论何种模式，都不得附上虚构的整封重写版本。
